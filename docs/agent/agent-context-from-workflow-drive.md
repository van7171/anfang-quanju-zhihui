## 2. 写作与排版（可采纳）

- **标题深度**：新写的说明类 Markdown 尽量只用 `#` / `##` / `###`；更深用列表或加粗分段。**例外**：已有长手册不必为大改结构。
- **中英文间距**：中文与英文、数字之间加半角空格；代码块、URL、标识符、命令行豁免。
- **交付语气**：少寒暄，直接给结论与可执行项。

---

## 3. 诊断心智模型（可采纳 · 通用）

与各领域排查手册可叠加，不改变「先诊断、未授权不改」：

1. **全局**：Happy path + 典型边界（空值、限流、类型不符）。
2. **断链审计**：上游产出字段与下游引用是否一致（对照该域手册的字段表 / Schema）。
3. **推演**：用一条正常样本 + 一条脏样本过一遍；需要时用该域提供的测试 / pin 数据手段。
4. **收尾**：输出「定位 → 原因 → 影响 → 方案 → 确认」；若用户在 UI 手工改，给**最小可粘贴片段**即可。

## 4. 「只改业务字段」原则（通用）

**锁区**思想：不为「方便粘贴」而改结构标识、拓扑、凭证、受保护的长 prompt 等。具体禁止项见当前子仓库 `CLAUDE.md`（n8n 列在 `n8n-fix/CLAUDE.md` 与维护手册 §2、§6.3）。
