## 二级：编排切片（业务层，便于拆需求）

把公众号相关自动化拆成 **五片**，你描述需求时尽量说是哪几片要动：

1. **入口**：表单 / Webhook / 定时 / 人工；是否幂等、是否允许重复提交。
2. **素材与生成**：配图、正文、模板变量；是否走外部 API（注意凭证与限流）。
3. **审核与人机**：谁点确认、超时策略、驳回后是否回写草稿。
4. **对外与通知**：是否只生成内容、还是同步发邮件 / 企微 / 其他渠道（与 [`SMART-DISPATCH-REQUIREMENTS.md`](project-docs/SMART-DISPATCH-REQUIREMENTS.md) 可对照「渠道与降级」思路，但不必混为同一流）。
5. **归档与证据**：推文链接、**人工截图或 PDF（带日期）** 存档；**不要**依赖对 `mp.weixin.qq.com` 的自动抓取正文（微信常返回「环境异常」，专利/对外材料里已反复强调）。

Agent 收到「公众号」但未说清切片时，应 **反问**你要动哪几片，再进入三级。

## 三级：工程层（改流前自检）

1. **图与编码**：`connections` 与 `nodes[].name` 必须一致；UTF-8 保存；整包 `PUT` 后建议跑 `tmp/scan-undefined-name.mjs`（见编码一致性文档 §5）。
2. **Code 节点**：注释里不要写假的 `$('节点名')`，避免静态扫描踩坑（见编码文档 §3）。
3. **红线**：不改 `id` / `type` / `typeVersion` / `position`、不改拓扑、不碰 `credentials`、不动长 Agent prompt 内部（见 `CLAUDE.md` 与手册「2 安全准则」「6.3 错误分类」）。
4. **激活**：`update_workflow` 后核对是否需重新 `active`（手册「2.3 激活状态」）。

---

## 四级：合规与材料（非 n8n 画布内）

若当前语境是 **专利 / 对外披露** 而不是日常运营：以任务书与交底书里 **「公众号证据固化」** 为准（人工打开链接 → PDF 或带日期截图 → 单独文件夹），**不把**抓取结果当唯一证据链。
